# ADR-0012: Articles Schema

## Context

The `articles` table is the central entity of BengalDesk. Every subsequent phase (editorial workflow, public rendering, search, analytics) joins against or references this table. Getting its column set, types, and constraints wrong now means a migration-and-backfill exercise later once RLS policies (2g), the Tiptap editor (4c), and the public renderer (6c) all depend on the schema being stable.

## Decision

### Column-by-column rationale

| Column | Type | Why this type / constraint |
|---|---|---|
| `id` | `uuid PK DEFAULT gen_random_uuid()` | UUID avoids enumeration attacks; `gen_random_uuid()` is built into Supabase Postgres (no pgcrypto needed). |
| `title` | `text NOT NULL CHECK (10–200)` | Bangla titles can exceed 200 chars in rare cases; 200 is a practical ceiling. Min 10 prevents empty or near-empty titles. |
| `slug` | `text NOT NULL UNIQUE CHECK (regex, ≤80)` | ASCII-only slugs generated by application-layer transliteration of Bangla titles (Phase 4e). Regex `^[a-z0-9]+(-[a-z0-9]+)*$` enforces the format. |
| `excerpt` | `text NOT NULL CHECK (≤160)` | Matches Twitter/metadata snippet length conventions. |
| `body` | **`jsonb NOT NULL`** | **Tiptap's native output format is a JSON document, not HTML.** Storing the raw JSON avoids a lossy HTML round-trip. Phase 4c's editor and Phase 6c's renderer both consume this JSON directly — any conversion layer would be a synchronization hazard. |
| `cover_image_id` | `uuid FK media(id)` | Nullable — not every article needs a cover image. References the media table (Phase 2e). |
| `category_id` | `uuid NOT NULL FK categories(id)` | Every article must belong to a category. References categories (Phase 2c). |
| `subcategory_id` | `uuid FK categories(id)` | Nullable — subcategories are optional. Self-referencing the same categories table. |
| `author_id` | `uuid NOT NULL FK profiles(id)` | The journalist who created the article. References profiles (Phase 2b). |
| `status` | `article_status NOT NULL DEFAULT 'draft'` | Enum with exactly 5 values: `draft → pending → published | rejected | scheduled`. This enum is the single source of truth for the editorial lifecycle. Every dashboard phase (4g, 5d, 5e, 5f) transitions between these values. |
| `breaking` | `boolean DEFAULT false` | Flags breaking-news articles shown in the ticker (Phase 6b). |
| `breaking_ticker` | `text CHECK (≤100)` | The short headline shown in the breaking-news ticker. Constrained by `breaking_requires_ticker` to be non-null when `breaking = true`. |
| `breaking_priority` | `smallint CHECK (1–3)` | Controls ticker ordering: 1 = highest. Only meaningful when `breaking = true`. |
| `breaking_expires_at` | `timestamptz` | Auto-expire breaking status. Application layer checks this on read. |
| `sponsored` | `boolean DEFAULT false` | Marks advertiser-paid content for FTC/ethical disclosure. |
| `premium` | `boolean DEFAULT false` | Gates content behind a paywall (Phase 5h). |
| `seo_title` | `text CHECK (≤60)` | Google truncates titles beyond ~60 chars. Nullable — falls back to `title` if not set. |
| `seo_description` | `text CHECK (≤155)` | Google truncates meta descriptions beyond ~155 chars. Nullable — falls back to `excerpt` if not set. |
| `reviewed_by` | `uuid FK profiles(id)` | The editor who reviewed this article. Set when status transitions to `published` or `rejected`. |
| `rejection_reason` | `text CHECK (≥20)` | Enforced by `rejected_requires_reason` constraint to be non-null when status is `rejected`. Min 20 chars prevents lazy rejections. |
| `submitted_at` | `timestamptz` | Set when author submits for review (draft → pending). |
| `scheduled_for` | `timestamptz` | Enforced by `scheduled_requires_time` constraint to be non-null when status is `scheduled`. |
| `published_at` | `timestamptz` | Set when status transitions to `published`. |
| `created_at` | `timestamptz NOT NULL DEFAULT now()` | Immutable creation timestamp. |
| `updated_at` | `timestamptz NOT NULL DEFAULT now()` | Auto-updated by `set_updated_at()` trigger on every row UPDATE. |

### Why body is JSONB, not HTML

Tiptap outputs a ProseMirror JSON document. Converting this to HTML at write time and back to JSON at read time is:

1. **Lossy** — HTML cannot round-trip all Tiptap node attributes (custom marks, extensions).
2. **A coupling hazard** — any change to Tiptap's schema would require a migration to update stored HTML.
3. **Unnecessary work** — the renderer (6c) and the editor (4c) both speak JSON natively. HTML is only generated at render time for the `<article>` DOM, not stored.

### Why RLS is enabled with zero policies

Between Phase 2a (table creation) and Phase 2g (policy creation), the table must be completely inaccessible to the `anon` and `authenticated` Postgres roles. The safe failure mode is "nothing is readable or writable" — not "everything is readable by anyone with a Supabase token."

Enabling RLS in the same migration that creates the table ensures there is no window where `articles` exists without RLS active.

### Why 5 indexes (not more, not fewer)

| Index | Covers |
|---|---|
| `idx_articles_status` | 4j (own-articles list filtered by status) |
| `idx_articles_category` | 6d (category page article lists) |
| `idx_articles_author` | 4j (journalist's own articles) |
| `idx_articles_published_at` (partial, `WHERE status = 'published'`) | 6b (homepage feed), 6c (single article lookup by slug+published) |
| `idx_articles_slug` | 6c (single article by slug) |

Additional indexes for future query patterns are added in their owning phase's migration, keeping blast radius scoped.

### Bangla & Unicode handling

All `text` columns (`title`, `excerpt`, `seo_title`, `seo_description`) accept Bangla text. Supabase Postgres defaults to UTF-8 database encoding — verified, not reconfigured. The `slug` column intentionally accepts only ASCII lowercase-and-hyphen; Bangla-to-Latin transliteration is the application layer's responsibility (Phase 4e) before INSERT.

## Consequences

- **Positive**: The schema is complete for the full editorial lifecycle — no column additions needed in later phases.
- **Positive**: JSONB body eliminates a conversion layer between editor and renderer.
- **Positive**: Deny-by-default RLS means no accidental data exposure during the 2a→2g gap.
- **Trade-off**: The `breaking_*` columns are nullable when `breaking = false`, adding some storage overhead per row. This is acceptable — the columns enable the breaking-news feature without a separate join table.
- **Trade-off**: `subcategory_id` references the same `categories` table as `category_id`, relying on application logic to prevent a subcategory from being used as its own parent. This is enforced in Phase 2c's categories schema via a `parent_id` self-reference.
